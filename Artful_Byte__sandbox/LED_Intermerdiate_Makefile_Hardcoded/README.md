## Overview

This sandbox introduces the IO driver that replaces the raw register writes from Stage 1. Instead of `P1DIR |= BIT0`, the code uses a typed enum API (`IO_TEST_LED`), a config struct, and the `io_set_*()` functions. `main.c` currently calls each `io_set_*()` one by one; the single `io_configure()` call is commented out for the next step. The watchdog disable is still in `main()` — `mcu_init()` has not been introduced yet.

This is where the lesson's hardest concepts live. The bit-packing trick and array-of-pointers dispatch are both implemented here.

---

## What This Demonstrates

- **Bit-packing enum (`io_generic_e`)**: each value encodes `[ zeros(3) | port(2) | pin(3) ]` in a single byte — `IO_10` = port 1 pin 0, `IO_27` = port 2 pin 7
- **Enum size**: the Makefile passes `-fshort-enums` so enums are 1 byte, matching the encoding comment in `io.c`
- **Array-of-pointers dispatch**: `port_dir_regs[]`, `port_out_regs[]`, etc. — port index extracted via mask+shift, no switch statement needed (arrays hold Port 1 only, `IO_PORT_CNT = 1`)
- **`struct io_config`**: groups select, direction, resistor, out into one call to `io_configure()`
- **Abstraction benefit**: `main()` refers only to `IO_TEST_LED` — changing the pin only requires updating the enum, not hunting through `P1DIR`/`P1OUT` calls

## Key Question This Sandbox Answers

> *How do you write an IO driver that works for any pin on any port without a switch statement per register?*

Answer: encode port+pin into the enum value itself, then use that value as an index into an array of register pointers. The bit-packing trick turns a symbolic name (`IO_TEST_LED`) into a port index and a pin bitmask — no per-port branching needed.
