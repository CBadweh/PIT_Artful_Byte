# .gitignore — Embedded Projects (CCS and Makefile)

**Summary**: What to ignore and keep in `.gitignore` for Code Composer Studio (CCS) IDE projects and plain Makefile/GCC projects on MSP430.

**Sources**: `Artful_Byte__sandbox/Blink LED/` (CCS), `Artful_Byte__sandbox/blink_example/` (Makefile), `Artful_Byte/.gitignore`

**Last updated**: 2026-07-21

---

## Code Composer Studio (CCS) Project

CCS is Eclipse-based. It generates two categories of files: IDE metadata and build output.

### Ignore

| Pattern | What it is | Why ignore |
|---------|-----------|------------|
| `Debug/` | Build output directory | Fully regenerated on every build — contains `.obj`, `.out`, `.map`, `.d`, generated makefiles |
| `Release/` | Release build output | Same as Debug — regenerated |
| `.ccsproject` | CCS-specific project descriptor | Machine-local, regenerated by CCS on import |
| `.cproject` | CDT (Eclipse C) project file | Contains absolute host paths — not portable |
| `.project` | Eclipse project file | Contains absolute host paths — not portable |
| `.settings/` | Eclipse workspace preferences | Machine-local editor/analysis prefs |
| `.theia/` | Theia IDE launch config | Machine-local debug launch config |
| `.clangd` | Clangd config file | Generated by CCS for LSP support |
| `**/.clangd/` | Clangd index cache directory | Binary index cache, fully regenerated |
| `*.obj` | Object files (CCS uses `.obj`) | Build artifact |
| `*.out` | ELF output binary (CCS naming) | Build artifact |
| `*.map` | Linker map file | Build artifact |
| `*.d` | Dependency files | Generated by compiler `-MD` flag |
| `*.opt` | CCS object list file (`ccsObjs.opt`) | Generated by CCS build system |
| `*.idx` | Clangd index files | Binary cache |

### Keep

| File | Why keep |
|------|----------|
| `*.c`, `*.h` | Source files — the actual work |
| `targetConfigs/*.ccxml` | Target config (device, connection) — needed for `flash` target and debugging |
| `lnk_msp430g2553.cmd` | Linker command file — controls memory layout, must be version-controlled |

## Makefile / GCC Project

Plain Makefile projects (no IDE) have a simpler structure. The Makefile controls where outputs go — typically `obj/` and `bin/`.

### Ignore

| Pattern | What it is | Why ignore |
|---------|-----------|------------|
| `*.o` | Object files (GCC uses `.o`) | Build artifact — regenerated by `make` |
| `*.elf` | ELF binary (GCC output naming) | Build artifact — regenerated by `make` |
| `obj/` | Object output directory | Regenerated by `make`; created with `@mkdir -p` |
| `bin/` | Binary output directory | Regenerated by `make`; created with `@mkdir -p` |

### Keep

| File | Why keep |
|------|----------|
| `*.c`, `*.h` | Source files |
| `Makefile` | Build script — defines the whole build |
| `*.ccxml` | Target config for `flash:` target (DSLite) |

---

## Key Difference: CCS vs Makefile

| | CCS | Makefile/GCC |
|---|-----|--------------|
| Object extension | `.obj` | `.o` |
| Binary extension | `.out` | `.elf` |
| Build dir | `Debug/` or `Release/` | `bin/` and `obj/` (Makefile-defined) |
| Extra ignore | `.cproject`, `.project`, `.settings/`, `.theia/`, `.clangd` | Nothing extra |
